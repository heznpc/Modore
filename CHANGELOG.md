# Changelog

All notable changes to this project are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning is informal pre-1.0 (semantic intent: bump minor on user-visible additions, patch on fixes).

## [Unreleased]

### Added
- **One Modore-owned agent and terminal entry point.** `bin/modore` and the tracked `modore-ops` Codex skill expose only session continuity, bounded storage status, native recovery navigation, cleanup recipe listing, and the read-only MCP tool inventory. Generic repository status, portfolio routing, Git, PR, publishing, full-system scan, cleanup preview/execution, and approval conveyance are absent by construction, so local AI-work and disk requests no longer need a separate product surface. Preview stays inside the native app because the existing preview protocol intentionally mints a live 15-minute approval token.
- **Storage-drop attribution evidence.** On an 8GB drop, entry below 20GB free, or a six-hour low-space follow-up, the hourly watcher records swap allocation plus at most three current-user processes by PID, RSS, and macOS's argv-free short executable name; argv is never collected. The same bounded event prioritizes the current user's Claude scratch root and a recent bounded set of exact `modore-*` temporary roots, while the storage scan follows tracked `Package.swift` manifests inside shallowly discovered Git repositories so nested SwiftPM `.build` directories no longer disappear from recovery. The Mac app presents RAM/swap signals separately from disk paths and labels them as contemporaneous evidence rather than proven causation. Agent-facing session commands now have process-tree wall-clock limits, so malformed local records cannot leave a task running indefinitely.
- **One native Work continuity surface.** The Mac app now groups repositories, primary checkouts, agent worktrees, and Claude Code / Claude Desktop Code / Codex conversations by canonical workspace. Explicit inspect/search/export stays masked; retirement assessment combines read-only Git state, sole-copy worktree evidence, and deep session binding, and incomplete discovery blocks a confident verdict instead of becoming “nothing found.”
- **Claude Desktop Code conversation units.** Scree now treats each `local_*.json` metadata record plus its same-stem directory as one conversation, rather than hundreds of unrelated JSONLs. Metadata listing, workspace binding, masked inspect/search/export, and byte-preserving backup all share the same bounded descriptor-based resolver; selected workspace folders are evidence only and are never traversed as conversation content.
- **Verified original session backup and restore.** A named Claude Code, Claude Desktop Code, or Codex session can be copied byte-for-byte into a versioned owner-only ZIP with exact inventory, sizes, SHA-256 digests, source-change detection, archive verification, safe-path checks, and create-new restore verification. The archive is explicitly unmasked and unencrypted, never resumes a provider session, and grants no cleanup permission.
- **Pinned standalone scree runtime.** Signed Mac builds embed a reduced python-build-standalone CPython 3.11 helper, verified by fixed upstream archive hashes, architecture/minimum-OS checks, nested signing, isolated `-I -B` execution, and an exact per-file runtime manifest consumed by artifact audit. A signed app never falls back to PATH Python.
- **QuotaPie as a narrow read-only producer.** The Work summary can present QuotaPie's semantic-v2 quota status by reading only `~/Library/Application Support/QuotaPie/quota.json`. Modore does not absorb its provider collectors, credentials, network calls, or lifecycle; missing or invalid boundary data is shown as unavailable rather than guessed.
- **Bounded Work and app lifecycle.** Modore is single-instance, cancels and drains automatic Work loaders on navigation and Cmd-Q, caps the outer scree report and repository assessment at 30 seconds, and keeps destructive transaction shutdown semantics intact. Repository measurements also stop at 100,000 working files or five seconds per path; Git, `du`, and `find` start from a fixed local directory so an unavailable external volume is reached only inside a cancellable process group. Runtime residue and exact owner-only scree scratch files left by a force quit are pruned on later use without touching unknown names, links, or active files, so recovery no longer depends on asking an LLM.
- **One official session surface for external operators.** `agent_session_list` and `agent_session_search` expose the native app's existing `scree sessions/search` engine through the read-only MCP boundary, so external local clients no longer need a Canary or Decant transcript parser of their own. Listing is metadata-only; search requires an explicit `user_initiated: true`, keeps its bounded query off argv by passing it through stdin, never exposes `--raw`, refuses results that do not affirm masking, and preserves scree's coverage and truncation verdicts.
- **Storage-pressure recovery is now a first-class app workflow.** A five-second local free-space signal keeps a persistent warning below 20GB and an urgent state below 5GB on every screen. The recovery page targets 20GB of headroom, chooses disposable caches before anything that needs downloading or rebuilding, shows one exact multi-item plan, and accepts one explicit destructive approval. Execution re-reads actual filesystem free space before and after each item, stops as soon as the goal is met, fails closed when measurement or approval freshness is lost, and has a 15-minute per-item process bound with the staging recovery path surfaced on failure. Apps, models, Simulator devices, and services stay outside the batch because their consequences require individual decisions. `modore://storage/recovery` opens this exact screen for a local operator without conveying a target or approval; noncanonical URLs, query strings, fragments, credentials, and ports are ignored.
- **Project build residue can be recovered through the same approval boundary.** `.build`, `node_modules`, Cargo `target`, Flutter/Gradle `build`, `.dart_tool`, `.gradle`, and `Pods` rows carry one fixed `project_residue` recipe while the dynamic path travels in a bounded pinned-FD request. Preview and execution revalidate the canonical HOME boundary, owner, non-symlink target, project marker, lockfiles, Git repository/index and tracked descendants, target identity and size, and relevant build processes; a changed or unreadable proof consumes the one-time approval and leaves the directory intact.
- **Mothball's destructive API is now unreachable from Modore by mechanism, not by intention.** Absorbing Mothball absorbed two different deletion disciplines. Modore destroys nothing without a preview that issues a single-use 64-byte approval token, a 15-minute owner-only manifest, a remeasure at the destructive boundary, and a receipt. MothballCore's `ArchiveOrchestrator.archive()` is careful in its own right — it refuses `/` and `$HOME`, verifies the archive before touching the original, and moves to Trash rather than unlinking — but it is an *in-process* Swift call that takes no token and consumes no manifest, and the vendor dependency already compiles it into Modore's binary. Nothing but review stood between a future `try orchestrator.archive(…)` in a view action and a second deletion path the approval chain never sees. Two tests now pin the boundary: any Modore source file that names `ArchiveOrchestrator`, `Restorer`, `ArchiveRun`, or `trashItem` must also carry the approval-token symbol, so a diff cannot introduce one half without showing the other; and `MothballService` is pinned to the read-only scan-and-classify surface it actually uses. Wiring the archive path stays allowed — wiring it *around* the token does not.
- **File-access reverse index — `scripts/fileaccess.py`.** Absorbed from canary's `get_file_access` / `getFileAccessAggregates` (that repository is a frozen paper archive; this was the capability Modore had no equivalent for). Inverts the evidence scree already reads: for each path, how many reads, writes, and shell references it received, from how many sessions, and when last — with agent rule and config surfaces (CLAUDE.md, AGENTS.md, settings.json, anything under `~/.claude` or `~/.codex`) sorted first and returned by default, because a silently edited rule file is the case the view exists for. The rule-surface taxonomy is carried over verbatim. **The content contract is stricter than the original's**: canary attached a 200-character excerpt of the shell command to every row, and that excerpt is command content, so it is dropped here — a path extracted from a command is metadata about which file was touched, the command that touched it is not. Only tool names and paths are retained; assistant text, tool results, and non-path tool inputs are discarded in the same pass that reads them, and nested subagent transcripts are never opened, matching scree's collector. Paths are canonicalised before aggregation, so a file reached as `/Users/x/.claude/settings.json` from a tool input and as `~/.claude/settings.json` from a shell command is one row rather than several. Dedupe is keyed on the tool_use block id — Claude streams one assistant message as multiple lines sharing a message id, so a path-keyed dedupe would silently collapse a genuine second read. Exposed as the `agent_file_access` MCP tool.
- **Hugging Face cache audit — `scripts/hfscan.py`.** Absorbed from decant's `ContextProbe.swift` (that repository is being retired; this was one of two capabilities Modore did not already have). Derives each cached model's identifier from its hub directory name (`models--Qwen--Qwen2.5-Coder-1.5B-Instruct` → the `Qwen/…` slug and the bare leaf) and searches the given roots for any occurrence, case-insensitively, so that over-catching keeps a model rather than losing one. **The original's central defect is inverted here.** decant returned "unreferenced" whenever the search could not run — a missing search root, a failed grep, a mistyped `--projects` argument all produced the same answer as a genuinely exhaustive search that found nothing, so one typo could mark an entire hub cache safe to delete. Absence of evidence is only evidence of absence when the search actually happened: a root that does not exist, a file cap reached, or a subtree that could not be read now yields `unknown` for every model with the reason stated, and `--allow-missing-roots` / `--ignore-unreadable` widen the verdict only when the operator asks. Metadata-only: file contents are matched in memory and discarded, and the only paths emitted are the files that *do* reference a model, masked through `scree.mask_text`.
- **MCP config hygiene — `scripts/mcpaudit.py`.** Absorbed from decant's `MCPHygiene.swift`. Reads `~/.claude.json` (including servers nested under per-project blocks), both Claude Desktop config locations, and `~/.mcp.json`, and reports entries that cannot start: `dead` (command does not resolve, or a script argument points at a path that is gone), `duplicate` (same command and args as another entry), `manual-review` (an `env` block is present), `unknown` (no command at all). Two deliberate deviations from the original: servers are named rather than anonymised to `server#N`, because a hygiene report the operator cannot act on is not one, and a server name is configuration metadata of the same kind scree already emits — while `env` is reported as a key *count*, never as keys or values. And a verdict that depends on PATH is withheld as `unknown` when PATH is unusable rather than reported as `dead`, the same fail-safe rule hfscan applies to its search. Read-only in the strong sense: the module has no code path that edits a config, disables a server, or starts one, pinned by a test.
- **Two more read-only MCP tools — `model_residue_report`, `mcp_hygiene`.** The audits above, exposed through the existing surface on the same terms as `agent_state_report` and `operator_friction_report`: allowlisted by name, annotated read-only and non-destructive, forwarding what the judgment script prints rather than reimplementing it. `model_residue_report` restates `search_complete` as a top-level `verdicts_withheld` flag so an incomplete search cannot be misread as "no orphans found", and its `roots` argument — the one place a caller supplies a path — is bounded to 8 entries and screened so a value can never be read as an option by the script it is passed to.
- **Leave-behind audit — `scripts/moraine.py`.** Reads the two records that outlive an uninstall — macOS installer receipts (`pkgutil`) and the admin/user trust domains (`security dump-trust-settings`) — and correlates them into a verdict neither produces alone: a trusted root certificate whose installing package has no payload left on disk. First live run on the development Mac found exactly that — `INNORIX.CA`, a self-signed `CA:TRUE` root valid to 2028-07-07, trusted unconditionally in the admin domain, installed 2026-05-01 by a Korean file-transfer plugin whose app, LaunchAgent, and processes are all gone. Receipts are judged `present`/`partial`/`vanished`/`no_payload` with any file sampling reported; roots with no owning receipt are `unattributed` (MDM profiles and enterprise Wi-Fi legitimately have none), never accused. Read-only: nothing is written and nothing deleted — removing a trust root is an admin act that stays a human decision. Exposed through the MCP surface as `uninstall_residue_report`.

### Changed
- **The scree pitch no longer claims the unpushed-work verdict is unique.** Orca's workspace cleanup runs the same `rev-list --not --remotes` check against the worktrees it manages, verified in its source. README now states the actual difference — scree sweeps every agent worktree on the machine whatever created it, plus primary checkouts stranded off main and registry entries whose directory vanished — and names the prior art instead of implying none exists.

- **Operator-friction scan — `scripts/friction.py`.** Deterministic port of canary's `lib/sessions/friction.ts` (that repository is now a frozen paper archive; this was its one capability Modore did not already have). Flags the user turns where the operator pushed back on agent behaviour, across nine categories — wrong-action, no-research-assertion, stalling-approval, rule-contamination, over-orchestration-token, stale-repetition, verbosity, tone-attitude, other-ai-friction — at severity 1-3. Keyword and tone matching only, no model in the judgment path. Claude Code and Codex sessions are discovered through scree's collectors; Gemini CLI chats (`~/.gemini/tmp/*/chats`, joined to a workspace through the project registry) and a dedicated Claude Desktop user-turn parser are layered on top. Scree now has its own bounded Claude Desktop conversation-unit collector for Work/list/inspect/backup, while friction retains its narrower user-authored-turn contract. Quotes are capped at 200 characters and masked by default (`--raw-quotes` opts out), and nothing is written. `--json` serves the structured report. First live run over a 30-day window: 200 sessions, 3,563 user turns, 430 findings (rage 247 / irritation 60 / correction 123).
- **Read-only MCP surface — `scripts/mcp_server.py`.** A zero-dependency stdio JSON-RPC server exposing three tools: `agent_state_report` (join, retention forecast, sole-copy and orphan verdicts, by section), `operator_friction_report` (the taxonomy above, filterable by store/category/minimum severity), and `system_scan_summary` (the storage and security scan result already on disk, with its age). Each tool runs `scree.py --json` or `friction.py --json` and forwards the output, so no judgment is reimplemented and the CLI, the Mac app, and the MCP surface cannot disagree. Cleanup, deletion, and scan execution are deliberately not exposed — Modore's destructive path is gated on an on-screen human approval, and an agent-reachable bypass would void it; pinned by a test that exercises every tool and asserts the only processes ever spawned are the two judgment scripts. The read-only contract is enforced where tools are registered, ported from AirMCP's own Swift MCP server (`IOSPreviewContract`): a tool is reachable only if it is on an explicit name allowlist and annotated read-only and non-destructive, so one added without a deliberate edit fails closed rather than being merely unlisted. All results are fenced as untrusted machine-derived data.
- **scree lineage: what the sessions remember versus what the disk still holds.** Every work path appearing in session records is classified alive+git / alive+plain / vanished, using existence and a `.git` presence check only; macOS case-variant ghosts (the same path recorded under different casings) are merged by casefold and reported once with their spellings. First live run: 422 paths — 118 alive git repos, 189 alive plain directories, 115 vanished (session records their only trace), 4 case ghosts. Consumers such as balance's lineup-gap diff read `--json .lineage`; scree itself reports universal facts only.
- **Stray primary-checkout judgment (scree).** Agent sessions can leave a repo's *main checkout* parked on a non-default branch with unmerged work — the same unique-work risk as an orphaned worktree, but invisible to worktree listing. `collect_worktrees` now judges the primary checkout of every repo that hosts agent worktrees: a non-main/master branch is reported as `stray_checkout` with the same protected-versus-rebuildable rules, and the report lists each one with its branch and unpushed count. First live run found 11 stranded checkouts, three of them carrying unpushed unique commits.

- **Recipe-less AI caches are now visible in the native app.** `ai_cache` items (Codex, and the newly-mapped Ollama/Kiro/VS Code/Gemini caches) carry no `cleanupId`, so they never qualified for `cleanupCandidates`, and they matched no other bucket either — an 11GB Ollama model cache was measured but shown nowhere. `developerToolchains` ("detected, not auto-cleaned" — already `project_residue`'s contract) now includes `ai_cache`, so these rows are visible without gaining a delete button.
- **scree residue coverage: Ollama, Kiro, VS Code, and Gemini CLI.** The storage scan now maps 25 additional paths across these four tools, splitting each into reclaimable caches (`ai_cache`, no cleanup recipe — view-only) versus protected session/credential state (`protected_history`): Ollama's SSH keypair and model blobs, Kiro's sessions/workspace state versus its editor caches, VS Code's user state versus its extension/GPU/data caches, and Gemini CLI's history/registry/settings versus its scratch tmp.
- **scree preserve — masked single-session export (Mac Edition).** `scree.py preserve <source>` reads exactly one caller-named session file (never auto-discovered) and exports it as Markdown with email/JWT/API-key/private-key/home-path redacted by default; `--raw` opts out explicitly. This is the one deliberate exception to scree's no-content-read contract, mirroring hydroject's single-session, mask-by-default `export`. Oversized files (>8MB) are refused rather than silently truncated.
- **Session & residue audit module — scree (Mac Edition, `scripts/scree.py`).** Joins local AI-agent traces (Claude Code, Codex, Gemini CLI, VS Code forks) by workspace/repository under a metadata-only contract: leading JSONL lines are decoded in memory but message content is never retained or emitted, and nested subagent transcripts are attributed by `stat()` without ever being opened. On top of the join it estimates per-store rolling retention windows and flags sessions near expiry inside still-living workspaces, marks orphaned workspaces with an explicit `orphan_basis`, and judges agent git worktrees protected-versus-rebuildable from read-only registry/push state — every verdict tagged `evidence: preview` with `requires_revalidation` so destructive consumers must re-verify before acting. `--json` serves the full result to external read-only consumers; the no-content-leak contract is pinned by tests.
- **Project build-residue detection (Mac Edition).** The storage scan finds rebuildable build artifacts *inside* development projects — Flutter `build/`+`.dart_tool/`, `node_modules/`, Cargo `target/`, SwiftPM `.build/`, `Pods/`, Gradle `build/`+`.gradle/` — under common dev roots (override with `PCH_PROJECT_SCAN_ROOTS`). These directories are gitignored and lumped into "Documents" by macOS, so multi-GB residue is otherwise hard to attribute. Rows keep the official regeneration command (`flutter clean`, `cargo clean`, …); the path-bound approval recipe described above now provides the guarded execution path without turning an arbitrary path into a recipe ID. Sub-4MB residue is skipped as noise.

### Fixed
- **Codex task lookup no longer turns into a minute-long transcript sweep.** `modore sessions current` now resolves the calling task from Codex process context, validates matching owner-only JSONL headers, and returns its physical rollout fragments without reading conversation bodies. The session index groups restart fragments by the per-task `id` while keeping spawned subagents separate from their inherited root `session_id`; logical and physical totals are reported independently, search scans every fragment with duplicate events collapsed, and `search --first` provides an explicitly incomplete fast path when exhaustive absence proof is not wanted. The Mac Work surface keeps the logical identity stable and labels multi-fragment conversations.
- **The retention forecast urged rescuing conversations their owner had already thrown away.** Deleting a conversation in the Claude desktop app rewrites only that app's own index — it removes the `local_<id>.json` entry and drops a `deleted_<id>` tombstone — and never touches the transcript. scree reads transcripts, so a deleted conversation looked like any other live session and its D-day flag read as "act before this is gone", arguing with a decision the owner had already made. The tombstones are now read as the one record on disk of that decision (filenames only; the body is a delete timestamp and is never opened, so this stays inside the metadata-only contract, pinned by a test that makes the tombstone unreadable and asserts the verdict is unchanged). Expiring sessions carry `owner_deleted`, sort below the ones still wanted so the head of the list is only ever actionable, and the text report names the third count beside "alive workspaces" and "orphaned". The Mac app reads the same flag and labels the row `앱에서 삭제됨 · 트랜스크립트 잔존` rather than reporting whether the workspace still exists, which is not the salient fact for a conversation already discarded; a scree that does not emit the key can never make the app claim a deletion happened. Nothing is hidden and nothing is deleted — the preserve action stays available, because whether to keep a discarded transcript is the owner's call. First live run: 23 of 80 expiring sessions (29%, 15.3 MB) had already been deleted in the app, including one of the five the report put in front of the user.
- **A Claude project directory whose path holds a non-ASCII component resolved to its parent instead of being left unresolved.** Claude names a project directory by replacing every non-alphanumeric character of the cwd -- not only the separators -- with a hyphen, so `/Users/x/집필` becomes `-Users-x---` and differs from `/Users/x` by hyphens alone. `_decode_claude_project_dir` segmented that name and tested each candidate with `(current / segment).exists()`, but `Path(x) / ""` is `x`, so the empty segments left by the collapsed characters each reported that they existed and the walk stopped early — returning `/Users/x`, a live workspace, as the confident answer for a directory that is gone. Sessions with no `cwd` in their leading lines, and every nested transcript attributed through the project fallback, were filed under the wrong workspace with nothing marking the guess. Resolution now matches on the encoded form the way the app does: a component that encodes to itself is still tried by name (one `stat()`, and it covers every plain ASCII path), only a level where no name matches is enumerated, a bucket that resolves to more than one directory is left unresolved rather than picked from, and the result must re-encode to the bucket it came from. On the development machine all eight live buckets round-trip exactly, three vanished ones are now unresolved instead of claiming an ancestor, one bucket under a symlinked path that previously failed to resolve at all now resolves, and two Korean directories of equal length are correctly reported as ambiguous. Eleven buckets resolve in 22 ms.
- **friction counted turns the operator never typed, and counted the ones they did more than once.** Two defects in the same question — what is one operator turn. (1) A `/compact` continuation is stored as `type: "user"`, but its body is the assistant's summary of the conversation so far. `NOISE_PREFIXES` does not match it and the pasted-report heuristic keys on 합니다체, which the English summary opens without, so the whole summary was read as operator text — inventing pushback nobody expressed and, worse, emitting assistant prose inside a quote attributed to the operator, against the store's own content contract. On the development machine one such row was a 10,886-character summary quoted as `stalling-approval` at severity 2, matching `라니까` inside the assistant's own recap. Rows are now skipped on `isCompactSummary` / `isVisibleInTranscriptOnly` rather than on the summary's opening sentence, which is English and would miss any localised build. (2) Resuming or forking a Claude session writes a fresh `.jsonl` replaying the whole prior conversation — every message keeps its `uuid` and `timestamp`, only `sessionId` changes — so a turn typed once sat on disk once per resume and was counted once per copy; one podium conversation held eleven copies of the same turn. Findings are now deduplicated across the store on (source, timestamp, quote), the same rule the Gemini parser already applies to `$set` rewrites, widened from within one file to across it; the newest-active copy survives, a turn with no timestamp is kept rather than guessed at, and the collapsed count is reported rather than quietly applied. First live run after the fix: 54 findings → 42, with the `stalling-approval` false positive gone and 30 replayed copies collapsed.
- **DMG artifact naming still carried the old brand.** `package_macos_release.sh` produced `PC-Health-Check-Mac-v…` archives in all three modes (local-unsigned, signed-not-notarized, release); they now emit `Modore-Mac-v…`, matching the README's `modore-v*` promise. Verified with a fresh `--local` dry-run.
- **README rename artifacts.** The title rendered as "Modore — Modore" since the product rename, and the release-artifact naming still promised `pch-v*` archives; both now match the Modore brand (`modore-v*`).

### Fixed (live UX pass on the Mac incident workflow — 2026-07-13)
- **Runaway browser automation can be stopped without killing the user's normal Chrome.** The development workspace now identifies Playwright/system-Chrome roots and ChatGPT, Codex, or Claude ancestry when available, reports bounded PID/profile/elapsed evidence plus estimated descendant RSS, and opens an explicit approval sheet before sending `SIGTERM` to an isolated browser or disposable temporary profile. It revalidates PID, parent, start time, real executable path, command identity, and profile immediately before acting; default and persistent custom Chrome profiles are ineligible, there is no automatic stop or `SIGKILL`, and a successful stop triggers a fresh scan.
- **Blocked cleanup previews identify the actual local blockers without exposing command arguments.** Live previews now show a bounded list of process categories with PIDs (for example, `Node/npm · PID 6095`) so the user can find the right process in Activity Monitor; test fixtures and the UI still never emit raw command lines, tokens, or URLs.
- **Collection coverage no longer overstates optional gaps.** When every required collector succeeds but optional collectors do not, the Security page now says that the required range completed, shows how many optional sources failed, and reserves the full-success shield for genuinely complete coverage.
- **Collected activity evidence is now inspectable instead of disappearing after classification.** The Security page exposes every collected process, external connection, and listening port with PID/path metadata, while still marking warning/danger rows and explicitly refusing to equate an unknown verdict with safety. New history entries retain bounded evidence counts so an expanded incident summary says what was actually collected without copying process paths into history.
- **Blocked cleanup previews no longer fabricate a 0KB re-measurement.** When related processes block a preview, `cleanup.sh` never measured the target, but the sheet still claimed "미리보기에서 0KB로 다시 측정했습니다" for directories that actually held gigabytes. The protocol now carries an explicit `estimateMeasured` flag; unmeasured estimates render as "측정 보류" with the last scanned value and retry guidance, in the sheet and the execution log.
- **Incident history rows are now readable.** Rows in 기록 truncated the judgment context to one line with no way to expand. Rows now expand in place to the full change description plus scan time, volume state, collection completeness, and the browser-automation verdict recorded at that time.
- **Protected-item descriptions match what the path actually is.** Claude Code project sessions were described as agent workspaces and Codex state databases inherited the event-log-DB copy; the Mac scanner now distinguishes session records, workspaces, state DBs, and event log DBs.
- **Stale evidence is flagged at the judgment, not only at the page bottom.** When the loaded result is old, the 현재 판단 card itself now carries the scan-age note.
- **Classified autorun entries show their risk.** Autorun rows with rule-engine warning/danger verdicts render with the same risk badge used elsewhere instead of being visually identical to unclassified entries.

### Fixed (adversarial second-pass audit — 2026-05-21)
- **Sysinternals Authenticode verification now runs on cached binaries.** Previous implementation only verified at first download; cached `.exe` under `%LOCALAPPDATA%` was trusted without re-verification on subsequent runs. Tools the project exists to detect (other user-mode malware) could have replaced the cached binary between runs.
- **CodeQL workflow removed.** Repository is private + free tier, which does not include GitHub Advanced Security. CodeQL runs failed every invocation with `Code scanning is not enabled for this repository`. The workflow was also wired into branch protection as a required check, silently blocking every PR from auto-merging. Workflow removed; required checks updated to `validate` + `powershell` only. PowerShell analysis remains covered by the existing parser check in `ci.yml`.
- **Result contract hardened.** Scanner failures no longer write raw facts into `scan_result.json`, and report generators reject raw facts that do not contain the classified `summary`.
- **Release smoke gate added.** OS-specific release zips are built from explicit allowlists and reject local scan artifacts, caches, and non-executable macOS launchers.
- **Report next actions added.** HTML reports now show immediate next steps and a reminder to redact local identifiers before sharing.
- **Runtime Python dependency removed.** Release zips now run with PowerShell on Windows and Bash + JXA on macOS. Python remains only for development tests, docs preview, and release-smoke packaging.

### Security
- **Release trust gate hardened.** Public Mac packaging now requires a clean exact version tag, builds from that immutable Git commit in an isolated workspace, validates Universal 2 slices and the macOS deployment target, removes build-machine prefixes/xattrs/ACLs, audits app/DMG payloads for secrets and personal paths, and publishes final names only after every signing/notary gate succeeds. Local unsigned DMGs and source ZIP smoke artifacts use separate non-overwriting paths and names.
- **User secrets removed from tracked configuration.** `data/config.example.json` is the only tracked default; ignored local or Application Support config files hold opt-in keys and are excluded from source ZIPs and app bundles.
- **CodeQL restored for the public repository.** Actions, JavaScript/TypeScript, and Python use fast build-free analysis. Swift remains covered by the required `macos-swift` build and test job because GitHub-hosted CodeQL extraction exceeded the practical pull-request budget.
- **Sysinternals Authenticode verification on every invocation.** `sigcheck.exe` and `autorunsc.exe` are verified via `Get-AuthenticodeSignature` against `O=Microsoft Corporation` not only at first download but **on every run**. The cache directory under `%LOCALAPPDATA%` is user-writable, so a cached `.exe` could be replaced post-cache by other user-mode malware (the scenario this tool exists to detect). Verification failure deletes the binary and falls back to fresh download.
- **CI workflow least-privilege.** `permissions: contents: read` set at workflow root. Default `GITHUB_TOKEN` scope reduced.
- **Landing page XSS hardening.** `docs/script.js` no longer interpolates raw `innerHTML` from translation JSON. A 30-line allowlist sanitizer keeps `<em>`, `<strong>`, `<code>`, `<a>`, `<br>`, `<span>` and strips everything else, including `on*` handlers and `javascript:` URLs. Defense-in-depth against malicious translation PRs.
- **VirusTotal API key — environment variable fallback.** `VT_API_KEY` takes precedence over ignored local/Application Support config. The tracked template never stores a key.

- **Standalone Mac app runtime.** The app now embeds an explicit allowlist of Bash/JXA/data/rule resources, validates its sealed bundle, and executes only the bundled scripts while keeping mutable output and configuration in owner-controlled Application Support. The staged mirror is checked byte-for-byte for migration integrity but is never executable input. Local DMG smoke packaging and opt-in Developer ID/notarytool distribution are scripted without storing credentials.
- **Swift safety tests.** SwiftPM tests now cover stable selection IDs, nested storage accounting, protected histories, cleanup protocol parsing, process-name presentation, and standalone runtime installation/config preservation.
- **Local Mac cleanup harness.** `scripts/cleanup.sh` provides allowlisted preview/execute recipes for rebuildable caches, Claude VM bundles, Xcode DerivedData, Chrome code-sign clones, and INNORIX-EX. Execute requires explicit approval, validates canonical non-symlink targets, checks related processes, rescans after completion, and writes a local receipt.
- **Native cleanup approval UX.** Actionable storage rows now open a SwiftUI preview sheet with estimated size, fixed targets, process blockers, and rebuild warnings. Protected AI histories and developer runtimes never receive an action ID.

- **One-time cleanup approvals.** Preview and execution are bound by a 256-bit, 15-minute manifest that rechecks target identity, tree size, process state, runtime integrity, Simulator keep/Booted state, and symlink boundaries immediately before and after an atomic staged move. Normal app termination waits for the destructive transaction boundary. Broad cache roots and protected Codex/Claude histories have no executable recipe.
- **Bounded process trees.** Native child commands now use an atomically created private process group, bounded nonblocking output drain, and TERM/KILL escalation so timeouts, cancellation, output overflow, and orphaned descendants cannot hang the app.
- **Hourly storage-drop watch.** The native app can toggle a local LaunchAgent that notifies below 20GB free or after an 8GB drop. It records free-space deltas and, after a large drop, an owner-only path-size snapshot of home-directory roots to attribute the cause; it never performs cleanup.
- **Storage change attribution.** The Mac app stores up to 180 owner-only scan snapshots, compares path sizes with the previous scan, and separates observed logical growth from untracked APFS/swap/temp-file changes.
- **Native Mac navigation redesign.** The first screen now answers current free space, change since the last scan, likely causes, and immediate actions before exposing cleanup, developer, app/Simulator, security, and activity details in separate native views.
